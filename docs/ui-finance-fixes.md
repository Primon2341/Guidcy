# Guidcy UI and earnings fixes

Changes are local to this workspace; no deployment, production mutation, or live payment charge was performed.

## Root causes and changes

| Issue | Root cause | Implementation / files |
| --- | --- | --- |
| Payment Back to profile | The button relied on browser history rather than the locked booking's consultant. The profile adapter also pushed duplicate history entries when the router was already at the correct URL, which broke Forward. | `assets/js/app.js`: `guidcyPaymentConsultantId`, `guidcyPaymentBack`, and `openProfile` adapter use the existing booking consultant ID and SPA navigation, and avoid duplicate profile history entries. Busy/payment locks remain in place. |
| Inconsistent rupee glyph | The self-hosted Latin font subsets excluded U+20B9, leaving the rupee to a different fallback font. Monetary displays also mixed manual prefixes, rounding, and locale formatting. | `assets/css/fonts.css`, four `assets/fonts/*-inr.woff2` files, and font preloads in `index.html` add U+20B9 subsets of the existing font families. `assets/js/app.js` adds the shared `guidcyFormatINR` using `Intl.NumberFormat('en-IN', {currency:'INR', style:'currency'})`; checkout keeps two decimal places. App and webinar currency renderers use it while preserving existing Free/empty-state meanings. Font provenance and licenses are in `assets/fonts/README.md` and the three OFL files. |
| Excessively heavy typography | Shared styles, inline templates, and generated styles repeatedly used 700/800 weights without a consistent hierarchy. | `assets/css/base.css` defines regular 400, medium 500, semibold/title 600, and brand 700 tokens. `assets/css/patches.css`, `assets/css/login.css`, `index.html`, `assets/js/app.js`, and `assets/js/webinar-flow.js` apply these tokens. Existing families and the brand's heavier weight remain. Standalone email HTML remains self-contained. |
| Earnings trend | The chart rendered fixed demo bars rather than booking data. Legacy dashboard wrappers could reject an accepted refresh as a duplicate; repeated restoration could restart slow queries. Failed queries also needed to remain distinguishable from empty results. | `assets/js/app.js`: Overview reuses its consultant-scoped bookings read. `guidcyEarningsMonths` aggregates 12 calendar months in IST using the existing payout eligibility predicate and payout calculation. Completion date is preferred, with session/creation date fallback for older records. Demo markup is replaced by real bars or “No earnings data yet”. Existing booking Realtime invalidates cached reads and refreshes the active tab. Legacy wrappers stop reinstalling after the route controller takes ownership; one in-flight read per dashboard tab prevents repeated reload queries, with one follow-up when data changes mid-read. The existing load-error Retry button now invokes the dashboard controller. Chart presentation is in `assets/css/base.css`. |
| Clipped My bookings title | An absolutely positioned skeleton pseudo-element covered the bottom of the heading during loading. It was an overlay collision, not truncated font glyphs. | `assets/css/base.css` places the skeleton below the title in normal document flow; `assets/css/patches.css` removes conflicting skeleton overrides. `assets/js/app.js` keeps the section title in the initial loading markup. Existing content remains during background revalidation. No artificial delay or heading concealment is used. |
| Remove payment overview card (latest request) | The reference-style checkout included a duplicate total and benefits column. | `index.html` removes the entire `pay-overview` aside. `assets/css/patches.css` centers a compact single column, with a width constraint that also survives older mobile max-width rules. Obsolete overview styles and DOM writes are removed from `assets/css/base.css`, `assets/js/app.js`, and `assets/js/webinar-flow.js`. Session and payment amounts stay in the primary form; webinar checkout includes its total in the primary summary. |

Earnings eligibility remains the existing settlement rule: verified successful payment, completed booking and session, and pending/paid payout status. The stored consultant payout is authoritative, with the existing payout fallback when absent. Neither gross customer payments nor pending/cancelled/unverified bookings are charted as earnings. No schema, RLS, payment creation/verification, fee, promo, meeting, email, or authentication provider changes were made.

## Follow-up: dashboard links and visible earnings amounts

The earlier URL-only mobile link check was insufficient: it did not ensure the requested dashboard content actually loaded. The replacement `tests/dashboard-tabs-browser.test.cjs` verifies content, selected navigation item, URL, refresh restoration and runtime errors for every registered tab.

- **Marketplace / Purchased Notes regression:** the legacy Marketplace `wrapRoutes()` ran from DOMContentLoaded and timers after the route controller initialized. It replaced the public dashboard switcher with a renderer that bypassed route ownership; My Marketplace could show its older sales table while the URL remained Overview. Purchased Notes also depended on that late wrapper registration. In `assets/js/app.js`, the legacy adapter now stops installing dashboard wrappers once the controller exists. `invokeDashboard()` explicitly dispatches the current existing Marketplace admin/seller/purchases renderers, passing the correct user or consultant panel ID. Existing purchase reconciliation remains in that call path.
- **Earnings amounts:** `guidcyRenderEarningsTrend()` in `assets/js/app.js` now displays the total earned during the displayed 12-month period plus each month's exact formatted INR amount. `assets/css/base.css` keeps the labels legible; on small screens the chart scrolls internally and opens on the most recent months. Eligibility and payout calculations are unchanged.
- **Admin Featured Experts:** full-tab verification uncovered a parent panel left in its loading state after the renderer updated only a nested container. `buildFeatureAdmin()` now commits its completed controls through the panel setter, and its caller returns the actual rendering promise instead of scheduling an untracked timer. Existing role/epoch guards remain.
- **Mobile drawer during loading:** the slow-font test reproduced the drawer closing on an ordinary late `pageshow` event. `assets/js/controllers.js` now closes on `pageshow` only for a back/forward-cache restoration (`persisted`), preserving a menu the user has opened during a normal load. Navigation, Escape, overlay and explicit close controls retain their existing behavior. `build-static.js` adds content-based cache versioning for this controller asset.

- **Delayed navigation registration:** Consultant Notifications and Admin Support Tickets were installed only after load/timers. A direct Notifications refresh rendered content without a selected sidebar item. Their existing navigation installers now also run synchronously before route initialization in `assets/js/app.js`; the final dashboard test explicitly includes both tabs.

Validation: all 43 registered tabs (11 user, 13 consultant, 19 admin) loaded correct content and restored after refresh at both 1280px and 390px. Marketplace-related tabs additionally passed three consecutive reloads and Back/Forward checks; fixtures included actual owned purchase/listing rows, rather than only empty states. The focused earnings/slow-load test passed at both widths, including visible totals/month values updating from ₹850 to ₹425, no earnings after cancellation, error/retry recovery, normal pageshow preserving the drawer and BFCache pageshow dismissing it. All 265 Node regression tests passed. These browser runs use controlled local Supabase fixtures and perform no production writes.
